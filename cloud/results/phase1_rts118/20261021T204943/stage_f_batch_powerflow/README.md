# 阶段F：展开点批量潮流与逐点牛顿-拉夫逊潮流的比较

计算入口：`python cloud/tests/run_stage_f_batch_pf.py`；计算程序`cloud/tmm_cloud/batch_powerflow.py`（按`01_IDEA/derivation.md`第1–2节实现，未知量含分布式平衡的系统不平衡量）。输入为阶段D两个运行点的建模场景（各5256个，float64存储），参照解为同一场景的逐点牛顿-拉夫逊潮流（阶段D结果，本阶段重算一次计时，两次结果逐位相同）。两种方法均为单个计算、单线程BLAS。

## 方法设置

- 按当前机组无功运行方式分组；每组首个展开点取设定量最接近组均值的场景，用牛顿-拉夫逊法求解；其余场景由式(8)二阶初值出发，最多10次固定雅可比修正（式(9)，步长1, 1/2, …, 1/2⁸中残差下降的最大步长），按式(10)判定收敛（残差≤10⁻⁸ p.u.，‖J₀⁻¹‖‖r‖≤10⁻⁷）；未收敛场景中‖J₀⁻¹‖‖r‖最大者作为下一个展开点，每组最多12个，其余改用逐点牛顿-拉夫逊潮流计算。
- 机组无功限值按第2.3节逐轮转换，每轮按新的运行方式重新分组。
- 另做一组已知最终运行方式的计算：直接按牛顿-拉夫逊解的最终机组运行方式分组，不经过转换轮次，用于区分分组数量与展开点修正本身的影响。

- 两个运行点的10512个场景全部收敛，机组最终无功运行方式与牛顿-拉夫逊解完全一致，电压误差均小于6.1×10⁻¹⁰ p.u.，远低于10⁻⁷ p.u.的要求；没有场景改用逐点牛顿-拉夫逊潮流计算。
- 每个分组只用了1个展开点：组内其余场景都在10次修正内收敛，展开点数量等于分组数。计算量由分组数决定。
- OP1的最终运行方式有689种，包含不少于50个场景的组合覆盖1700个场景，其中98.7%由修正求解。
- OP2的最终运行方式有3165种，最大的组合只占0.8%，2270种只出现一次，没有包含50个以上场景的组合。66.4%的场景本身就是展开点，相当于逐点求解，加速降至1.9倍。原因是OP2基础运行点有14台机组距无功限值不足1 Mvar，新能源误差使17台机组在0.2%–69%的场景中达到无功限值（阶段E），运行方式组合数随之增多。`mode_pattern_sizes_<OP>.png`给出各运行方式组合的场景数分布。

## 判断

- 展开点批量潮流在IEEE118两个运行点的建模场景上达到逐点牛顿-拉夫逊潮流的精度（误差<10⁻⁹ p.u.，运行方式一致），已由数值实验支持。
- 加速比由机组无功运行方式组合的集中程度决定：OP1为6.3倍，OP2降至1.9倍；即使事先知道最终运行方式，OP2也只有3.0倍。在多台机组接近无功限值的运行点，按完整运行方式分组会使展开点批量方法接近逐点求解（已由数值实验支持，限于本阶段两个运行点）。
- 可能的改进是对运行方式只相差少数机组的场景共用展开点，并对雅可比矩阵做低秩更新；这一改进代码尚未实现，效果尚未验证。
- 计时为单线程、5256个场景，未计入多个并行计算或更大批量下的变化，结果待复核。
